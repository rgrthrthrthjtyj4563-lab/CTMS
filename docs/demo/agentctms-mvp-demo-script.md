# AgentCTMS MVP 5 分钟投资人演示脚本

- 版本：v1（Demo Freeze 冻结用）
- 日期：2026-07-17
- 目标：在 5 分钟内讲清并演示"CRA 一次 IMV 如何被 Agent 重构"
- 受众：投资人 / 临床运营背景非技术评审
- 一句话开场：AgentCTMS 不是让 CRA 多填一张表，而是把一次现场录入，自动拆成 PM 可审核、QA 可追溯的业务结果。

## 0. 演示前提（提前 30 分钟准备）

1. API 在 :3001 运行（`pnpm --filter @clinical/api start`），DB 已 seed；
2. APP 指向 `http://localhost:3001`（Expo 默认读取 `API_URL` 环境）；
3. 演示账号已通过 `pnpm --filter @clinical/api db:seed:demo` 切到 ZZ-101/上海六院上下文：
   - CRA：`13800138001` / `password`（李明）
   - PM：`13800138002` / `password`（王芳）
   - QA：`13800138003` / `password`（张磊，后置）
4. 演示专用项目/中心/历史 Issue/今日 IMV 由 `pnpm --filter @clinical/api db:seed` 已写入；
5. 回滚 CRA/PM 默认上下文：`pnpm --filter @clinical/api db:reset`；
6. 演示使用 iPhone 模拟器竖屏；录屏使用 QuickTime + 模拟器；
7. 关闭所有通知、勿切演示页面，保持前台。

## 2. 5 分钟分镜

| 时段 | 讲（30 字以内） | 演示动作 |
|---|---|---|
| 0:00–0:30 | 痛点：CRA 一次 IMV 平均要填 8 张表 | 黑底白字一段：今天 CRA 现场有 IMV... |
| 0:30–1:00 | 演示账号登录；今日 IMV 在工作台 | 移动端登录 → 工作台显示今日 IMV |
| 1:00–1:30 | 简报带上下文：历史 Issue + 重点 | 点今日 IMV → IMV 简报页 |
| 1:30–2:00 | 开始访视 → 进现场 | 点"开始访视" → IMV 进行中 |
| 2:00–3:00 | 一段口语 / 一张照片 → 系统收事实 | 输入上面那段固定口播 + 上传 1 张药房温度记录照片 |
| 3:00–3:30 | 结束访视 → 2 秒内出行动包 | 点结束访视 → 自动跳行动包 |
| 3:30–4:30 | 行动包：候选/来源/状态 一屏讲清 | 翻看"监查记录/工时/Issue/Risk/CAPA/任务/证据/报告/跟进"全部点亮 |
| 4:30–5:00 | 逐项确认 + 提交 → PM 一秒通过（控制演示节奏） | 勾选全部确认 → 提交 → 切 PM 账号看通过 → 切回 CRA 看最终状态 |

> 录屏剪辑版（D5）从 5 分钟分镜中取 0:30–3:00 + 3:30–4:30，约 2 分钟。

## 3. 演示稳定性的工程护栏

1. 行动包一律走 `parseWithRules` 兜底，关闭真实 LLM 依赖；
2. `ai.ts` 不读 `TEXT_LLM_API_KEY` 即纯本地 deterministic；
3. seed 内置 IMV、今日输入样例、附件占位、Issue 历史；
4. confirm 回写已经过 `normalizeGeneratedPack` + `ACTION_CONFIRMED_FALLBACK` 双护栏；
5. e2e 单测走 `:3001 + seed` 必须绿（演示前跑一次）；
6. 录屏前若发现任何 UI 偶发抖动，优先回退 UI，不动规则解析。

## 4. 演示事故兜底

| 场景 | 兜底 |
|---|---|
| 模拟器卡顿 | 重启 Expo；D0 备一台冷启动镜像 |
| 网络抖动 | 现场手动提交；不依赖网络重新生成 |
| 行动包缺类型 | seed 强制 2 附件 + 1 口播，保证 rules 输出齐全 |
| PM 审核不显示 | 直接跳 API：演示事先通过 curl / `reviews` 提交一条 |
| 投资人要延长 | 用 D5 录屏补完"AI vs 人工"对照页与路线图 |

## 5. 演示后 1 分钟收口（讲）

> AgentCTMS 的护城河不是页面数量，而是把 CRA 一次 IMV 的事实，结构化成 PM 可审核、QA 可追溯的结果。下一步从 IMV 单点扩展到全部 MonitoringVisit 与多 Agent 协同，但 AI 永远只输出候选，正式动作永远由人确认。
